## Bounds, ordering and authorization

- Existing BA-05 discovery: 250 ms tick, one in-flight page of 10 bindings, two concurrent Organizations, four worker database connections; discovery errors retry no faster than 5 s. Per-tenant publication failure cannot starve later tenants and participates in unhealthy-sweep readiness.
- Publisher: at most 100 rows/transaction; validates Organization actor/binding and current active Session authority owned by the configured Deployment. An Organization transaction advisory claim serializes batches across processes. Rows publish in Evidence order; publication/attempt count commit together. No long provider transaction, cache, event bus or general job platform is added.
- Client: one finite replay request at a time, normally every 1 s; 10 s abort deadline; transport fallback and exponential retries capped at 30 s. Empty batches do not reload authoritative projections. Only affected Runtime/effect/adjudication views refresh, with full scoped recovery for snapshots or Release activation.
- Existing server bounds remain 100 replay rows and 101 retained cursor rows per device. Client deduplication keeps the latest 512 IDs in arrival order. Cursors stay in memory and advance only after refreshed data is saved; page restart acquires a new snapshot. The encrypted Offline Outbox remains the sole persistent local Command state, including `local_pending`, receipts and reconciliation outcomes.
- Every sync/projection read resolves current principal, device, Organization, Session, Seat and Active Role Context server-side. New metadata is selected from the same authorized projection functions; private IDs/bodies are not sent for later UI hiding. Scope/permission changes invalidate cursors or deny reads. SQL remains tenant scoped; closed-channel selection uses the same invitation/role/stage rules as live projection.
- Scope and request generations reject old asynchronous responses; cache writes serialize and projection-only updates preserve the latest stored Command/receipt. Unmount/Session change/logout abort subscriptions and timers. Access/device revocation clears protected offline data. Authentication expiry clears projections while retaining local drafts for reauthentication.

These are arithmetic limits and local test observations, **not** measured representative throughput. A 205-row recovery test establishes bounded progress, not supported multi-tenant capacity or an end-to-end delivery SLO. BA-11 must rehearse actual deployment sweep latency; BA-12 must rerun app/voting load and retains the existing voice latency blocker.
