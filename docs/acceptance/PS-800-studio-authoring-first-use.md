# PS-800 Studio authoring first-use task

Status: **NOT RUN — human gate**.

Use a fresh disposable local user-test fixture and a person who has not seen the revised Studio workstation. Do not describe where controls are located. Record observable behavior and the participant's words; do not infer comprehension from clicks alone.

## Task prompt

> Resume the Fractured Order Draft. Confirm you are editing the right Core Design and Scenario, change one Team description, find out whether the Draft can move to review, and preview what a Scribe sees during Orientation. Leave the Draft synchronized. You may use browser Back, Forward and reload whenever you want.

## Observer record

Record PASS, FAIL or NOT RUN for each item and note where the participant paused, backtracked or requested help.

1. Opens the Project Draft from Projects without entering an identifier.
2. States the Core Design, Scenario, Organization and current role context from visible information.
3. Finds Teams from the task-grouped Draft map or mobile workspace picker.
4. Edits one existing Team description and distinguishes **Saved on this device** from **Synchronized**.
5. Uses Draft checks to state whether review is available. If an issue exists, uses its plain-language workspace action and identifies the focused control.
6. Opens Role walkthrough, selects Scribe and Orientation, and runs the preview without navigating to Runtime.
7. Reloads once and confirms the selected workspace is restored; uses Back/Forward and explains the resulting workspace change.
8. Finishes with no pending synchronization and can name the next governed step.

## Blocking observations

Any wrong-Draft edit, loss of an unsaved field during workspace switching, inability to recover from a validation issue, mismatch between visible and announced context, or belief that preview changed Runtime is a release blocker for this slice. Record the exact state, viewport, input method and recovery attempted.
