PS-830 D adds `form-expression-v1` and `formatted-text-v1` inside opted-in `structured-form-v2` definitions. The expression contract has a required Formula version scoped to the immutable Governing Release and Form version. Its declarative tree supports arithmetic, scalar comparisons, conditional values, counts and totals over declared repeating groups; maximum 100 nodes and 8 levels. Arithmetic uses finite JavaScript numbers within ±Number.MAX_SAFE_INTEGER, with declared output precision applied by decimal rounding. There is no clock, random source, external state, network or executable code. Publication rejects cycles, missing references and any dependency excluded by an owning Artifact Type's Information Policy. Runtime rejects missing evaluated inputs, division by zero, invalid types and overflow, and replaces supplied computed values before final validation. Conditional branches evaluate only the selected result. A new Formula/Release does not reinterpret historical submissions.

Formatted text stores plain text with a limited formatting grammar: paragraphs, flat lists, emphasis and HTTP(S) links without URL credentials. Shared parsing produces escaped text and allowlisted elements, never HTML execution. HTML, images, embedded content and disallowed link schemes are rejected. Limits: 200 blocks, 2000 inline segments, 2000 list items and the overall structured byte ceiling. Definition defaults, Runtime validation and rendering share the parser. Exports retain the original text and pinned contract. The transport contract references the schema package's computation type through a type-only internal workspace dependency, avoiding a competing expression model; no external dependency was added.

PS-420 implements the approved `keep_existing` choice from ADR-004/OPEN-008. It does not offer in-place migration or cross-schema/compiler activation. Disruptive definition or security-topology changes require a new Session and the approvals recorded in OPEN-008. Artifact-targeted Commands continue under the Artifact's pinned Release; Commands against a changed Session aggregate must reconcile after activation.

Trust roots and revocation documents are provisioned independently of Plugin bundles. Bundles carry only key identifiers; they cannot add or replace trust roots. Private signing keys and Plugin secret references are never stored in Releases, bundles, or this registry.

## 2026-11-08 approval implementation alignment

PS-830 E focused automated verification passed: `form-interchange-v1` is owned by Simulation Schema. Definition files retain Form identity/version and declared structure. Record files retain Artifact, Form/version and Governing Release, typed authorized payload and an optional attachment manifest; manifests explicitly exclude bytes and preserve file identity/digest/scan/retention pins. Imports never copy file authority or bypass ordinary record Commands. Definition input is limited to 2,000,000 UTF-8 bytes; record content still obeys its pinned structured contract. CSV previews support 100 data rows and 100 columns within the structured byte ceiling, with explicit distinct root-field mappings and typed validation. Repeating groups export as separate tables linked by record/section/entry identifiers. CSV neutralizes spreadsheet formula prefixes; JSON preserves exact strings. PDF uses the existing readable text renderer for printable ASCII and explicitly refuses unsupported characters rather than corrupting them. Protected fields and hidden defaults are omitted at the server projection/history/export boundary; protected input is denied without value-dependent feedback and omitted values survive edits.

`form-attachments-v1` is an explicit optional policy inside `structured-form-v2`; `form-attachment-upload-v1` describes the upload envelope. File types are plain text, Markdown, PDF, PNG and JPEG, verified against content. Policy references resolve to immutable, applicable automatic-deletion Retention Policies at freeze/publication/import and upload. Unsupported archive/anonymization policies cannot enable file attachments. Commands are `artifact.attach_file` / `artifact.rescan_file`; events are `artifact.attachment_added` / `artifact.attachment_rescanned`. Transport accepts an empty client Command payload and derives canonical metadata/digest server-side. A 27,000,000-byte endpoint-specific JSON ceiling accommodates bounded base64 while other HTTP bodies retain their existing ceiling. No download is available until clean; only failed scans can be retried. Records retain Governing Release/Form pins. Focused E verification is recorded in the checkpoint evidence; it is not a PS-830 completion claim.

The additive `readiness-v1` staffing properties `people` and `peopleTruncated` support direct assignment and reserved invitations by display name. Only the existing authorized Session Operator receives active members of the same Organization; results exclude contact information, are limited to 100, and can be narrowed through the existing bounded `query` parameter. Existing consumers can ignore the optional properties. Assignment Commands, roles and trust boundaries remain unchanged. The E integration and published-file browser verification passed.

PS-830 must extend the existing simulation/form contracts with explicit versions and demonstrate historical Release, form/formula and submission readability. Renderer, server validation and export must agree. Exact byte units and bounded submission size must be specified and tested. PS-845 must version any transfer operation and preserve monotonically increasing epochs, receipt identity and evidence continuity. PS-820 reruns affected prior-version upgrade/restore tests; PS-850 validates the converged candidate. No new production contract identifier is allocated by this promptbook.

The optional `completionRequirements` on an Inject Definition uses Simulation Schema `inject-completion-v1` with `acknowledgementRequired`. Mutation and projection recheck the active recipient selector and content Information Policy. Per-recipient progress never includes other recipients? content.
