# PS-520 reporting data dictionary and retention matrix

Updated: 2026-10-26.

## Data dictionary

All `reporting` rows are Organization-scoped and protected by forced row-level security. Records are append-only except for the one-way, trigger-guarded removal of expired export bytes; export identity, digest, manifest and purge provenance remain immutable.

| Record | Purpose | Authority and provenance |
|---|---|---|
| `report_definitions` | Versions report kinds, included/excluded data classes, and analytical layers | Definition contract and creator |
| `measurement_definitions` | Versions derived-metric questions, formula, interpretation, risk, validation, and export shape | Measurement key plus immutable version |
| `research_consents` | Records participant grant or withdrawal for one named research purpose | Participant, purpose, consent version, decision, recorder, time |
| `retention_policies` | Records institution-approved retention behavior without inventing a default duration | Policy key/version, scope, days, legal-hold behavior, expiry action, destination, approval requirement |
| `legal_hold_events` | Append-only placement and release history that suspends eligible export disposal | Hold ID, Organization/export scope, reason, actor and time |
| `analytical_records` | Keeps analyst notes and findings separate from captured observations and derived metrics | Analyst, layer, source references, confidence, limitations, time |
| `corrections` | Preserves the original and corrected value as a compensating record | Actor, reason, time, and report-regeneration flag |
| `export_jobs` | Makes export requests idempotent and immutable | Request digest, idempotency key, definition, requester, completion time |
| `export_artifacts` | Stores generated bytes until expiry while retaining immutable provenance after byte disposal | Job, media type, filename, SHA-256, manifest, creation time, purge actor and purge time |
| `organization_imports` | Records one digest-verified logical restore idempotently | Source digest, complete source manifest, importer, restored-row count in the audit record, time |

Standard reports read canonical Releases, Sessions, Evidence Events, versioned measurements, and analytical records. Research exports additionally require the Research Analyst role, an active project grant, and current purpose-specific participant consent. Research observations omit event bodies and replace participant/aggregate identifiers with export-local references. Secret Ballot choices and protected voice assets are excluded.

## Organization logical restore contract

The `plenum-organization-logical-v1` archive rehydrates its declared Organization data into a separately migrated deployment. Import is fail-closed: the archive digest, restore contract, source Organization reference, Organization ID, Organization name, dataset shapes, and every row's Organization scope must match. The target must contain only the same Organization and its bootstrap Admin identity; project, Runtime, Evidence, and reporting tables must be empty.

Restore inserts the declared people, memberships, projects, Studio publication dependencies, Releases, Sessions, authorities, activation history, participants, Artifacts, Evidence Events and checkpoints, report definitions, research records, policies, corrections, and prior export records in one database transaction. A failed row rolls back the entire import, and replaying the same archive digest returns the original import ID without duplicating data.

Authentication credentials, audit-record details, Secret Ballot choices, protected voice assets, and object-store blobs are not transported by this logical archive. Those systems must be provisioned or restored separately; PS-530 owns that deployment/backup work.

## Retention matrix

| Data class | Current PS-520 behavior | Approved production policy |
|---|---|---|
| Evidence Events, Audit Records and signed checkpoints | Preserved; PS-520 never rewrites or deletes them | Seven years; legal hold suspends disposal; redaction or compensating records must preserve chain verification |
| Sessions, Artifacts, Messages, non-secret Polls and reports | Canonical and append-only history retained | Seven years; corrections remain linked to affected records |
| Release packages and verification keys | Preserved for reproducibility and proof verification | At least as long as the Evidence they verify |
| Research consent | Grant and withdrawal history retained; current decision controls future exports | Seven years after the associated research ends |
| Export jobs and artifacts | A daily production timer removes up to 10,000 eligible artifact payloads per tenant-scoped run after 90 days. Active Organization/export holds suspend disposal; completed runs and hold changes write Audit Records. Metadata and SHA-256 remain for provenance, while replay of a purged artifact fails closed. | 90 days, then audited deletion unless under legal hold |
| Operational logs and metrics | Outside the reporting schema and must exclude protected content and secrets | 90 days |
| Organization archives/imports | Digest-verified logical data is restored transactionally into an empty same-Organization deployment; duplicate import is idempotent | Encrypted and retained under the seven-year source-record policy; object-store recovery remains with PS-530 |
| Rolling encrypted backups | Restored through PS-530 controls | 35 days in a separate failure domain within the same legal jurisdiction |
| Unsynchronized offline drafts | Encrypted local storage under OPEN-014 | 30 days maximum |
| Secret Ballot choices and protected voice assets | Excluded from PS-520 reports and portable archives | Not created in version 1 because secret ballots, recording and transcription are disabled |

OPEN-009 was resolved on 2026-10-26. Production data stays in institution-controlled PostgreSQL and S3-compatible storage in the institution-selected legal jurisdiction; encrypted backups stay in the same jurisdiction but in a separate failure domain. Sethu Nguna is the operational owner. Migration 025 and the packaged service now enforce the 90-day generated-export period with legal-hold and audit controls. Institution-owned scheduler observation, storage lifecycle checks for non-database classes, and owner acceptance remain operational release evidence.

## Migration and recovery

`024_reporting_research` is additive after migration 023. It creates a schema, tables, indexes, RLS policies, grants, and append-only triggers without rewriting existing rows. Older application versions ignore the new schema. Rollback stops report/research writes and preserves all generated artifacts and provenance; after use, recovery is forward-fix or database restore coordinated by PS-530, not table removal.

`025_security_retention_enforcement` adds the shared request-window store, append-only legal-hold events and nullable export payload/purge-provenance columns. Existing export rows satisfy the new constraint without rewriting bytes. Deploy migration 025 before the new application. Rollback stops the new application timer and preserves every row; after any purge, use a forward fix or the approved backup restore because removed payload bytes are intentionally not reconstructed from metadata.
