# PS-520 reporting data dictionary and retention matrix

Updated: 2026-10-23.

## Data dictionary

All `reporting` rows are Organization-scoped, protected by forced row-level security, and append-only. The application role has `SELECT` and `INSERT` only; database triggers refuse update, delete, and truncate operations.

| Record | Purpose | Authority and provenance |
|---|---|---|
| `report_definitions` | Versions report kinds, included/excluded data classes, and analytical layers | Definition contract and creator |
| `measurement_definitions` | Versions derived-metric questions, formula, interpretation, risk, validation, and export shape | Measurement key plus immutable version |
| `research_consents` | Records participant grant or withdrawal for one named research purpose | Participant, purpose, consent version, decision, recorder, time |
| `retention_policies` | Records institution-approved retention behavior without inventing a default duration | Policy key/version, scope, days, legal-hold behavior, expiry action, destination, approval requirement |
| `analytical_records` | Keeps analyst notes and findings separate from captured observations and derived metrics | Analyst, layer, source references, confidence, limitations, time |
| `corrections` | Preserves the original and corrected value as a compensating record | Actor, reason, time, and report-regeneration flag |
| `export_jobs` | Makes export requests idempotent and immutable | Request digest, idempotency key, definition, requester, completion time |
| `export_artifacts` | Stores exact generated bytes and a provenance manifest | Job, media type, filename, SHA-256, manifest, time |
| `organization_imports` | Records one digest-verified logical restore idempotently | Source digest, complete source manifest, importer, restored-row count in the audit record, time |

Standard reports read canonical Releases, Sessions, Evidence Events, versioned measurements, and analytical records. Research exports additionally require the Research Analyst role, an active project grant, and current purpose-specific participant consent. Research observations omit event bodies and replace participant/aggregate identifiers with export-local references. Secret Ballot choices and protected voice assets are excluded.

## Organization logical restore contract

The `plenum-organization-logical-v1` archive rehydrates its declared Organization data into a separately migrated deployment. Import is fail-closed: the archive digest, restore contract, source Organization reference, Organization ID, Organization name, dataset shapes, and every row's Organization scope must match. The target must contain only the same Organization and its bootstrap Admin identity; project, Runtime, Evidence, and reporting tables must be empty.

Restore inserts the declared people, memberships, projects, Studio publication dependencies, Releases, Sessions, authorities, activation history, participants, Artifacts, Evidence Events and checkpoints, report definitions, research records, policies, corrections, and prior export records in one database transaction. A failed row rolls back the entire import, and replaying the same archive digest returns the original import ID without duplicating data.

Authentication credentials, audit-record details, Secret Ballot choices, protected voice assets, and object-store blobs are not transported by this logical archive. Those systems must be provisioned or restored separately; PS-530 owns that deployment/backup work.

## Retention matrix

| Data class | Current PS-520 behavior | Production decision |
|---|---|---|
| Evidence Events and signed checkpoints | Preserved; PS-520 never rewrites or deletes them | Duration, archive tier, residency, legal hold, and disposal approval remain `OPEN-009` |
| Report definitions, measurements, notes, findings, corrections | Append-only and retained | Same `OPEN-009` decision; corrections must remain linked to affected artifacts |
| Research consent | Grant and withdrawal history retained; current decision controls future exports | Legal basis and retention period remain `OPEN-009` |
| Export jobs and artifacts | Exact bytes retained so retries return the same artifact; regeneration creates a new artifact | Expiry, archive destination, and approval remain `OPEN-009` |
| Organization archives/imports | Digest-verified logical data is restored transactionally into an empty same-Organization deployment; duplicate import is idempotent | Archive lifetime, encryption, custody, object-store recovery, and disposal remain `OPEN-009` and deployment operations in PS-530 |
| Secret Ballot choices and protected voice assets | Excluded from PS-520 reports and portable archives | Their separate policies remain governed by the voting/media decisions, not PS-520 |

PS-520 stores approved policy records but does not run deletion or anonymization jobs. In simple terms: no data is automatically destroyed until the institution decides the legal rules in `OPEN-009`. That decision is not automatically solved by another coding prompt; PS-550 must keep release approval blocked until an authorized owner records it, while PS-530 supplies the deployment/archive mechanisms that apply it.

## Migration and recovery

`024_reporting_research` is additive after migration 023. It creates a schema, tables, indexes, RLS policies, grants, and append-only triggers without rewriting existing rows. Older application versions ignore the new schema. Rollback stops report/research writes and preserves all generated artifacts and provenance; after use, recovery is forward-fix or database restore coordinated by PS-530, not table removal.
