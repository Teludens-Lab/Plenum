01 · FOUNDATIONS

One identity. Multiple products.

Teludens sits above universal interface quality standards and defines the opinionated identity, behavior, geometry, and product feel shared across Teludens tools.

01

Calm computational power

Capability is deep; presentation stays quiet. Complexity is organized, not dramatized.

02

Structure before decoration

Hierarchy comes from geometry, typography, tone, boundaries, and state before ornament.

03

Direct manipulation

Objects preserve continuity through state change. Selection, ownership and context do not teleport.

04

Progressive density

Focus, Standard, and Operations use the same architecture at different information compression levels.

05

Consequence-aware UI

Information, interpretation, intention, action, and consequence remain perceptually distinct.

06

Motion communicates causality

Movement answers what changed, where it came from, and what it now affects.

02 · COLOR

Material first. Signal second.

Graphite establishes the working environment. Mineral Sage is reserved for consequential decisions and meaningful relationships. Neutral selection and accessible focus remain distinct from semantic status signals.

SIGNAL / DECISION

Mineral Sage is not the focus color.

Mineral Sage marks consequential paths, committed decisions, and approved state transitions. Selection uses neutral tonal emphasis; keyboard focus uses a dedicated high-contrast ring. Generic primary actions remain graphite; destructive actions remain crimson.

Motion is system feedback.

Routine interaction stays below 300ms. Motion must communicate causality, continuity, orientation, feedback, or hierarchy—and remain interruptible.

15 · FEEDBACK & RECOVERY

Every consequential action has a recovery path.

Notifications must convey what happened, whether anything changed, and what can happen next. Test inline validation, recoverable failures, undo and permission denial.

Ready to inspect

Choose an event to see the appropriate level of feedback and recovery.

No authoritative change
Feedback hierarchyInline for field errors · local status for async actions · toast for reversible acknowledgment · persistent banner for blocked work · confirmation dialog for irreversible consequences. Never mark an action successful before the server confirms it.

16 · ICONOGRAPHY & SYMBOLS

Symbols must carry stable meaning.

One restrained outline vocabulary, with controlled optical weight. Distinguish action, object, state and role without relying on color alone.

Consistent 24×24 viewBox · round joins/caps · 1.75 stroke · no decorative fills
Semantic rulesAction icons use verbs; entity icons identify nouns; role authority is conveyed by a labeled role indicator; state uses shape + text, with color as reinforcement. Icons do not replace labels for consequential operations.

20 · GUIDANCE

Rules that protect the system.

A design system is a behavior contract, not a screenshot archive. The catalog exposes the reusable rules; runtime products still need accessibility, performance, keyboard, responsive, and reduced-motion validation.

DO

Preserve object continuity.

Selection, inspector context, scroll position, and proposal identity should survive state transitions whenever the mental model survives them.

DO

Reserve signal.

Strong color and motion should mean something. Focus and selection should not be mistaken for commitment. A0–A2 content does not get promoted with animation.

AVOID

Card mosaics.

Prefer continuous working surfaces, aligned lists, panels, tables, rails, and contextual inspectors over repeated floating rectangles.

AVOID

Generic motion.

No scale-on-hover, persistent floating, decorative bounce, queued transitions, or motion without causality.
